# Передача Mystic NFT Drop заказчику

Этот файл — чек-лист передачи проекта. Передача означает, что заказчик получает собственный экземпляр проекта и контроль над его инфраструктурой. Не передавайте личные пароли от своих аккаунтов.

## 1. Что получает заказчик

- Исходный код проекта.
- Собственный GitHub-репозиторий или переданный ему репозиторий.
- Собственный сервис хостинга и адрес HTTPS.
- Собственного Telegram-бота, настроенного на URL Mini App.
- Инструкцию по настройке переменных окружения и запуску.

## 2. Что должен создать заказчик

Попросите заказчика подготовить:

1. GitHub-аккаунт и репозиторий, принадлежащий ему.
2. Аккаунт хостинга (например, Render) и веб-сервис из этого репозитория.
3. Telegram-бота, созданного через @BotFather, либо согласовать безопасную передачу управления существующим ботом.
4. Токен бота. Токен вводится только в секретные переменные хостинга — не в исходный код, не в переписку и не в публичный репозиторий.

## 3. Переменные окружения

Настроить в панели хостинга:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота заказчика |
| `ADMIN_IDS` | Telegram ID администратора заказчика |
| `DEV_MODE` | `false` для production |
| `DB_PATH` | Путь к постоянной базе данных, если выбран SQLite |
| `WEBAPP_URL` | Публичный HTTPS-адрес Mini App, если используется приложением |

Не публикуйте реальные значения переменных в GitHub и не добавляйте файл `.env` в репозиторий.

## 4. Развёртывание

1. Заказчик импортирует репозиторий в свой хостинг.
2. Проверяет команду сборки: `pip install -r requirements.txt`.
3. Проверяет команду запуска: `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`.
4. Добавляет переменные окружения из раздела выше.
5. Запускает сервис и проверяет адрес `/api/health`.
6. Настраивает URL Mini App в Telegram через @BotFather.
7. Открывает Mini App в Telegram и проверяет авторизацию, профиль, вращение и инвентарь.

Для SQLite нужна постоянная файловая система/диск. На временном диске данные могут исчезнуть после перезапуска или нового развёртывания. Для реального проекта заранее согласуйте постоянное хранилище или внешнюю базу данных.

## 5. Проверка перед передачей

- [ ] Заказчик открывает Mini App со своего Telegram-аккаунта.
- [ ] Приложение корректно загружается по HTTPS.
- [ ] Профиль и инвентарь работают.
- [ ] Данные сохраняются после перезапуска сервиса.
- [ ] В репозитории нет токенов, паролей и личных ключей разработчика.
- [ ] Заказчик получил доступ к своему GitHub, хостингу и Telegram-боту.
- [ ] Заказчик подтвердил, что всё работает.

## 6. Что важно сообщить заказчику

Текущий проект — прототип Mini App. Экран пакетов Telegram Stars пока демонстрационный: реальные платежи не подключены. Также нельзя считать внутренние виртуальные баллы реальными Telegram Stars. Не запускайте платное пополнение или платную случайную выдачу предметов, пока отдельно не реализованы и не проверены платежи, правила платформы и применимые требования закона.

## 7. Завершение передачи

После проверки:

1. Убедитесь, что заказчик действительно владеет своим репозиторием, хостингом и ботом.
2. Передайте согласованные материалы и инструкции.
3. Удалите собственный доступ к клиентским ресурсам, если это предусмотрено договорённостью.
4. Не удаляйте исходный шаблон разработчика автоматически: эксклюзивная продажа с отказом от повторного использования — отдельное условие сделки, которое нужно согласовать и оценить отдельно.

**Безопасное правило:** заказчик получает собственные аккаунты и секреты; разработчик не передаёт свои личные аккаунты и не отправляет токены в чат.
